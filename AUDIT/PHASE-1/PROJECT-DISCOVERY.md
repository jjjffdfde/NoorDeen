## 1. Executive Summary & Discovery Findings

An independent, rigorous inspection of the actual workspace at `E:\islamic websiye` reveals that the project is an active, zero-dependency full-stack static web application paired with an embedded Node.js ES Module HTTP server (`server.js`) and a hybrid mobile application scaffold configured with Capacitor (`capacitor.config.json`, `android/`).

### Key Confirmed Findings:
1. **Runtime Framework:** The active, served application is 100% vanilla HTML5, CSS3, and ES6 JavaScript located in `public/`. It does not execute via Next.js or React. An orphan `src/` directory containing TypeScript files (`.ts`, `.tsx`) from an earlier Next.js prototype exists in the repository, but is completely unreferenced by `server.js`, `public/`, and the test runner.
2. **Package Manifest:** `package.json` specifies `"type": "module"` and `"main": "server.js"` with zero external npm runtime dependencies. No `node_modules` directory exists or is required to run the web server or the test suite.
3. **Automated Test Suite:** `test/run-tests.js` executes 264 automated assertions across 21 test suites using native Node.js (`http`, `fs`, `vm`, `crypto`, `assert`). All 264 assertions pass. However, these tests predominantly verify string matching, file existence, VM sandboxed functions, local HTTP GET statuses, and link resolution. They do **not** verify headless browser rendering, visual layout, true viewport reflow, Dalvik bytecode execution, or complete verse coverage for all 114 Surahs.
4. **Quran Architecture (Critical Finding):**
   - Metadata for all 114 Surahs and canonical verse counts (6,236 total) are cataloged in `public/js/data.js`.
   - **Only 10 Surahs** (1, 36, 67, 97, 108, 109, 110, 112, 113, 114) are bundled offline with complete Arabic, English, and Urdu verse text.
   - For the remaining **104 Surahs**, `public/js/quran.js` depends on runtime client-side `fetch` calls to an external third-party API (`https://api.alquran.cloud/v1/surah/...`). When offline or disconnected, users viewing any of these 104 Surahs receive an offline fallback card rather than scripture.
5. **Hadith & Dua Dataset Reality:**
   - While `public/hadith.html` presents a filter dropdown for all six canonical books (*Kutub al-Sittah*), the underlying dataset `ISLAMIC_DATA.hadiths` in `public/js/data.js` contains **only 8 Hadiths total**. *Sunan Ibn Majah* has 0 records.
   - `ISLAMIC_DATA.duas` contains **only 17 supplications**.
6. **Android APK Build Reality (Critical Finding):**
   - The file `public/downloads/islamic-portal-release.apk` (142,692 bytes) is generated by `scripts/package-apk.js`, which packages web assets into a PKZIP archive with an uncompiled plain-text `AndroidManifest.xml`.
   - It is **not** a valid Android binary compiled by `aapt2` / `d8` with Dalvik bytecode (`classes.dex`) or an Android APK v2/v3 signature. Consequently, it cannot be installed directly on standard Android devices without compilation through the real Android Gradle toolchain (`./gradlew assembleRelease`).

### 3.1. Routing & Server Model
- **Implementation:** Built directly upon Node.js `http.createServer` with ES module imports.
- **Clean Route Mapping:** Uses `ROUTE_ALIASES` to map URL endpoints like `/quran` to `/quran.html`, `/history` to `/history.html`, etc.
- **REST Endpoints:**
  - `GET /api/health` -> `{ status: "healthy", timestamp: "...", version: "1.0.0" }`
  - `GET /api/languages` -> `{ count: 40, note: "Complete 40-language framework..." }`
- **Security:** Sets standard HTTP security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`. Disallows directory traversal outside `public/`.

### 3.2. Translation & i18n Architecture
- **Dual Translation Model (Strict Separation of Concerns):**
  1. **UI Language Engine (`public/js/i18n.js`):** Controls page interface labels (`data-i18n`). 40 languages are cataloged; 11 have full dictionary mappings (en, ur, ar, fr, id, tr, bn, hi, ms, fa, es). Implements `snapshotDefaultDOM()` to store original English text nodes in memory, allowing instantaneous lossless restoration when reverting to English.
  2. **Quran Translation Engine (`public/js/quran.js`):** Completely decoupled from UI language. Selecting an Ayah translation language via `#quran-trans-lang-select` updates **only** the verse translation panel and persists to `islamic_portal_quran_trans_lang` in `localStorage`. It never modifies the global navbar or page chrome.
- **40-Language Translation Registry (`data/quran-translations/registry.json`):**
  - Catalog of 40 language editions.
  - Verified editions: Urdu (*Fateh Muhammad Jalandhry*), English (*Saheeh International*), French (*Muhammad Hamidullah*), Indonesian (*Indonesian Ministry of Religious Affairs*), Turkish (*Diyanet Isleri*), etc.
  - Languages without peer-reviewed digital texts display an explicit theological review badge rather than inaccurate machine translations.

### 3.3. Quranic Arabic Text Protection
- In `public/js/quran.js`, every Arabic verse container is strictly wrapped as:
  `<div class="ayah-arabic font-quran" lang="ar" dir="rtl" translate="no">`
- The `translate="no"` attribute prevents Google Chrome and automated translation extensions from tampering with divine revelation.
- Verse numbering matches the Hafs 6,236 verse standard.

### 3.4. Offline & Android Architecture
- **PWA Service Worker (`public/service-worker.js`):** Implements a cache-first network fallback strategy under cache name `islamic-portal-shell-v2`. Audio files are cached under `islamic-portal-audio-v1`.
- **Capacitor Configuration (`capacitor.config.json`):** Points to `webDir: "public"`, `appId: "com.islamicknowledge.portal"`.
- **Permissions:** `android/app/src/main/AndroidManifest.xml` specifies only:
  - `android.permission.INTERNET`
  - `android.permission.ACCESS_NETWORK_STATE`
  Zero invasive permissions (no location, contacts, camera, or microphone).
- **Packaging Limitation:** As identified, `scripts/package-apk.js` creates a ZIP wrapper named `.apk`. A true production APK requires compilation through the Android SDK Gradle wrapper (`./gradlew assembleRelease`).

## 5. Summary of Verified Technical Dependencies

1. **Node.js (v18+ recommended):** Needed to run `server.js` and `test/run-tests.js`.
2. **External API (`api.alquran.cloud`):** Runtime dependency for Ayah text and translations for 104 Surahs.
3. **External Audio CDN (`everyayah.com`):** Runtime dependency for reciter audio streams.
4. **Android SDK / JDK 17:** Required for real Gradle compilation of the Capacitor Android project (currently uncompiled in `downloads/`).
5. **No NPM Package Dependencies:** Zero third-party npm packages required at runtime, providing exceptional long-term stability and security.
